## NUGGETS AT RISK

1. **The required v3 migration reader does not exist.** The spec requires a Git-pinned reader/verifier and differential command ([spec:1677](</Users/mikewolfd/Work/DocSpec/docs/superpowers/specs/2026-08-05-docspec-standalone-platform-implementation-spec.md:1677>)), but repository-wide searches found no migration command, receipt type, pinned revision, v3 digest, differential fixtures, or tests. DocSpec only accepts `docspec-document-release/1.1` ([release.py:181](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/release.py:181>)); its package-boundary test explicitly classifies every v3 module as archived ([test_package_boundary.py:70](</Users/mikewolfd/Work/DocSpec/tests/test_package_boundary.py:70>)).

2. **Exact segment-to-rendition reversibility is missing from release verification.** v3 proves contiguous ordinals, complete normalized-text coverage, UTF-8-safe coordinates, text digests, and equality with the exact rendition-pack byte slice ([document_release_v3_verify.py:728](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:728>), [document_release_v3_verify.py:828](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:828>)). DocSpec checks interval containment and mapped evidence ([delivery.py:499](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/delivery.py:499>), [delivery.py:669](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/delivery.py:669>)), but does not require contiguous/full representation coverage or compare each segment blob’s bytes with the referenced representation slice.

3. **The closed reconciliation universe and eligibility proof are missing.** v3 requires every selected or previously active document to have exactly one consistent `active`, `deleted`, `excluded`, or `accepted-failure` disposition; it binds current state, failures, change rows, eligibility evidence schema/digest/verdict, inventory digest, and coverage totals ([document_release_v3_verify.py:584](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:584>), [document_release_v3_verify.py:708](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:708>), [document_release_v3_verify.py:1012](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:1012>)). DocSpec validates individual disposition rows and only the disposition→source direction ([delivery.py:577](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/delivery.py:577>), [delivery.py:708](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/delivery.py:708>)); `commit.py` computes layer counts rather than those semantic balances ([commit.py:105](</Users/mikewolfd/Work/DocSpec/src/docspec/application/commit.py:105>)). No eligibility model or verifier exists under `src/docspec`.

4. **Partition reuse is lost at the final release artifact boundary.** v3 retains partition-scoped manifests and members ([document_release_v3_writer.py:1260](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_writer.py:1260>)). DocSpec storage correctly reuses unchanged content-addressed partition members ([storage.py:1114](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:1114>)), but final publication streams every complete layer into one new `records/*.jsonl` member ([platform_artifact.py:275](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/platform_artifact.py:275>)). That does not preserve partition-level physical reuse in the published release.

5. **DocSpec’s diff is less informative than v3’s exact active-set diff.** v3 performs a bounded full outer join and emits old/new document-version IDs with `add`, `delete`, `update`, or `eligibility` ([document_release_v3_diff.py:53](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_diff.py:53>)). DocSpec’s CLI compares layer references and count deltas only ([cli.py:1595](</Users/mikewolfd/Work/DocSpec/src/docspec/cli.py:1595>)); catalog comparison reduces record differences to `added`, `deleted`, or `changed` ([storage.py:1743](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:1743>)). It cannot reproduce v3’s eligibility-change classification or old/new version table.

6. **Stable first-failure verification codes are absent.** v3 exposes registered codes for format, membership, digest, path, schema, identity, foreign-key, coordinate, evidence, and reconciliation failures ([document_release_v3.py:116](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3.py:116>), [document_release_v3_verify.py:1094](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:1094>)). DocSpec’s semantic verifier raises textual `IntegrityError`; its standalone CLI only reports root parsing as `structurally-valid` ([cli.py:1577](</Users/mikewolfd/Work/DocSpec/src/docspec/cli.py:1577>)).

7. **The v3 compaction trigger policy has no counterpart.** v3 measures inactive document/evidence/passage rows and recommends compaction above a 10% inactive ratio or eight delta generations ([document_release_v3_compact.py:80](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_compact.py:80>)). DocSpec’s compactor proves logical equivalence but provides no measurement or recommendation policy ([maintenance.py:392](</Users/mikewolfd/Work/DocSpec/src/docspec/application/maintenance.py:392>)).

8. **Same bytes with conflicting media types are no longer rejected.** v3’s rendition writer deduplicates SHA-256 bytes across partitions and fails if identical bytes claim different media types ([document_release_v3_writer.py:577](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_writer.py:577>)). DocSpec’s content-addressed store reuses the digest-addressed object while accepting the caller’s new media type; verification checks bytes, size, and locator, not prior media-type consistency ([storage.py:353](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:353>), [storage.py:461](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:461>)).

## SAFELY SUPERSEDED

- **Format identity and canonical JSON:** v3 is `spicyregs-document-release/3.0`, with content-derived IDs, closed manifests, embedded schema vocabulary, and canonical integer-only JSON ([document_release_v3.py:25](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3.py:25>)). DocSpec replaces it with its own closed `docspec-document-release/1.1` root and canonical identity rules ([release.py:21](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/release.py:21>), [identity.py:112](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/identity.py:112>)).

- **Complete membership, path safety, digests, schemas, and atomic visibility:** v3 verifies every declared file, rejects missing/extra/symlinked members, and publishes only after verification ([document_release_v3_verify.py:335](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_verify.py:335>), [document_release_v3_writer.py:1434](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_writer.py:1434>)). DocSpec reproduces this through Rulespec artifact admission and semantic verification before exclusive publication ([platform_artifact.py:321](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/platform_artifact.py:321>), [storage.py:1644](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:1644>)).

- **Rendition packs:** v3 writes indexed, digest-checked packs with within-release deduplication ([document_release_v3_writer.py:516](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_writer.py:516>)). DocSpec safely replaces packs with individually content-addressed, chunk-written, range-readable blobs ([blob_store.py:12](</Users/mikewolfd/Work/DocSpec/src/docspec/ports/blob_store.py:12>), [storage.py:330](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:330>)).

- **Bounded writing:** v3 bounds Parquet batches by rows and estimated UTF-8 bytes ([document_release_v3_writer.py:434](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_writer.py:434>)), although one rendition is loaded fully and may exceed the nominal pack target ([document_release_v3_writer.py:858](</Users/mikewolfd/Work/spicy-regs/src/spicy_regs/document_release_v3_writer.py:858>)). DocSpec enforces hard blob, record, member, open-handle, and merge-scratch limits ([storage.py:330](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:330>), [storage.py:1057](</Users/mikewolfd/Work/DocSpec/src/docspec/adapters/storage.py:1057>)).

- **Cross-layer uniqueness and lineage:** Much of v3’s DuckDB validation is reproduced, engine-independently, by DocSpec’s disk-backed SQLite verifier: unique identities, exact file→representation→segment lineage, partition placement, and referenced blob verification ([delivery.py:253](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/delivery.py:253>), [delivery.py:640](</Users/mikewolfd/Work/DocSpec/src/docspec/domain/delivery.py:640>)).

- **Compaction equivalence:** DocSpec improves on v3’s active-identity comparison by hashing every ordered logical record before and after compaction and refusing any change ([maintenance.py:356](</Users/mikewolfd/Work/DocSpec/src/docspec/application/maintenance.py:356>), [maintenance.py:410](</Users/mikewolfd/Work/DocSpec/src/docspec/application/maintenance.py:410>)).
