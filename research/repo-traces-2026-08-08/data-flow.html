Five repos, one workspace — where the data actually goes

A diagnostic of every edge that crosses a repo boundary: what mechanism carries it, what volume moves, and which edges are broken, dead, or severed at the source.

Evidence rule. Every number and edge below was re-derived from code or data by a tracer that read the file — never quoted from a receipt, manifest, or .md. Figures that could only be found asserted are marked asserted. Where two tracers disagreed, the disagreement is printed rather than resolved. Observations are as of 2026-08-09; RefSpec HEAD moved twice during the trace (7e9a6f1 → 287937a → 21b662a) and its working tree carries 2,858 modified files, all under bindings/atlas/3.0.

Read this first — the ground moved during the trace. RefSpec commit 5c6d889 “refactor(atlas): retire Atlas 1.0 and 2.0” (2026-08-09 14:46, 307 files changed, 468 insertions, 20,711 deletions, 63 files deleted outright) removed bindings/atlas/1.0/examples/, bindings/atlas/1.0/fixtures/ and the whole of bindings/atlas/2.0/, and dropped build_vocabulary_atlas from the public API. Its message reads “Greenfield, no consumers.” That is true of RefSpec’s own code paths and false of the workspace: SpicySearch and RuleSpec both hold digest-pinned byte-copies taken from exactly those deleted paths. Nothing breaks at runtime today, because each consumer keeps its own copy — but the upstream those digests point at no longer exists, so no copy can be re-derived or re-verified. That is drawn below as a severed pin: a distinct failure from a merely stale one.

Version skew

Both consumers read Atlas 1.0. RefSpec builds 3.0. The gap is not one major but two — and as of today the intervening surface has been demolished rather than deprecated.

What is genuinely healthy

  • The pack pipeline. Every Atlas 3.0 pack carries dual digests — content (uncompressed canonical) and transport (zstd) — computed in one streaming pass at generate_atlas_v3_full.py:5673. Publication is atomic by candidate-directory rename.
  • The parquet view chain has a real digest check that runs. parquet_view.py:659 verifies the view manifest digest, canonical payload digest and per-table schema digest; its test file passes 9/9.
  • DocSpec’s content-addressed storage is deterministic by construction. Blob keys are observed, not chosen — bytes are streamed through SHA-256 and the digest becomes the path. There is no uuid, random, secrets or token_hex anywhere in src/docspec/, floats are forbidden in identity payloads, and every minted URN recomputes itself in __post_init__ and raises on mismatch. You cannot forge one.
  • DocSpec’s package boundary is test-enforced, including a test that inspects the built wheel for any archive path component.
  • SpicySearch’s snapshot verifier works. It correctly refused a stale snapshot when run — the broken snapshot below is the verifier doing its job, not failing at it.
  • RefSpec → RuleSpec is the model executable edge: git-SHA pinned against an evidence revision, guarded by a clean-tree check, behind a required --rulespec-dir flag.
  • The RuleSpec → RefSpec closure pin is the single best-behaved edge in the workspace. Not one file digest but a 45-artifact closure — two commit revisions, twenty generated-artifact digests, plus corpus, constraint and self-certification digests. Its evidenceRevision matches RuleSpec HEAD exactly, and running make audit-rulespec-pin reports “45 upstream inputs found; immutable closure pin verified”. Worth knowing how it got there: it had silently gone ten commits stale because its only test used a synthetic fixture and never touched a real checkout — it was found broken and repaired today. It is still opt-in rather than part of the default test target.
  • The one atlas pin that is actually enforced. RuleSpec's release records verify RefSpec's minted atlas identity at read time and raise AtlasIntegrityError on mismatch — confirmed by a live tamper test, not by reading the code.
  • DocSpec's clean-room tripwire runs and passes. Its fingerprint pin is inverted — it asserts DocSpec's code must not resemble the SpicyRegs snapshot it forked from — and it is a hard assertion with no skip path.
  • SpicyRegs firewalls its own dependency. Five tests install an __import__ hook that raises on any refspec* name, and a sixth walks the AST statically, to prove designated paths stay clean.

Disagreements, corrections and what remains unverified

Where this diagram contradicts the 2026-08-08 traces

  • “Nothing reads the 2.6 GB build” is wrong as stated. It is read inside RefSpec by parquet_view.py:606. It is dead cross-repo only. A different, milder pathology.
  • “One unset REFSPEC_CHECKOUT disables every cross-repo freshness check” is wrong in both directions. It gates exactly one RuleSpec test class. SpicySearch’s equivalents fall back to vendored copies and run; one of them bypasses the variable entirely and is live right now.
  • The biggest dead artifact was missed. 8.7 GB of hidden orphaned build candidates, against the 2.6 GB that was reported.
  • refspec is not importable from RuleSpec. The earlier trace had this backwards; the relevant test is named test_refspec_output_round_trips_without_importing_refspec.
  • The two atlas readers are not “262 identical lines differing only in exception type.” Real diff: 430 deletions / 633 insertions.
  • 715,080 appears in no JSON receipt or parquet anywhere — only in .md files. The “a receipt outlived its input” story rests on a figure that is not in a receipt.
  • Zero value-ring statements is wrong — there is exactly one. (subject 559,946 · entity 481 · value 1 · null 1.)
  • Counts corrected: 21 rollups not 22; 9 materialised tables (32 logical); 9 production refspec imports not 8; 5 import-hook tests not 7; 96 urn:ref families not ~5; 105 stable_urn call sites not 86; ≥12 canonical-JSON implementations not 6; 3 live document-release readers not 4; 51 RefSpec output dirs not 49; DocSpec archive 598 files / 259,524 insertions not 591 / 259,613.
  • DocSpec’s live src/ does have a network client (boto3 S3). The claim that it has none is false; the true, narrower claim is that it has no REST client.
  • SpicySearch does make network calls — to OpenAI and Google. Only “no government host” survives.
  • api.usaspending.gov is not duplicate live traffic. RefSpec reads a pinned local fixture; the fetch path is dormant. Only uscode.house.gov and the mirrulations bucket are genuinely fetched twice.
  • The broken SpicyRegs imports are worse than “modules moved.” Three of four targets were deleted outright with no successor; only one moved.
  • “The torn catalog’s test skips rather than fails” is unfair to that test. It fails on ordinary drift — it has its own test proving so — and suspends only for the specific, provable case where the upstream pin has torn itself. The defect is real but it is a deliberate, narrow escape hatch, not a blanket skip.
  • Cross-repo byte-identical files: 120, not 69 (828 instances), driven by growth in the RuleSpec↔SpicySearch fixture corpus. The important half of the claim survives intact: zero .py files are byte-identical across live repo boundaries — fixtures were copied, code was re-implemented.
  • RuleSpec’s vendored corpus was never refreshed even once. It was taken on RuleSpec’s first-ever commit from RefSpec’s first-ever corpus commit. “7 of 21” understates it: one vendored case was later renamed away upstream, so only 6 of the 7 still correspond to anything that existed at deletion.
  • The relation_sssom.py digest pin was already stale before the deletion (cf7ea940 pinned vs f655e158 actual), and the validator never recomputed a hash — it regex-checked the digest’s shape. A pin that is never recomputed is decoration.
  • SpicySearch keeps a second, entirely unpinned copy of the atlas — byte-identical to the pinned one, with no digest file and only a hardcoded path in test modules.

Where the tracers disagreed

Two tracers described test_policy_inputs_cross_repository.py in opposite-sounding terms — one called it “actively running a live cross-repo comparison,” the other reported it skipping. Both are right and the diagram states the reconciliation rather than picking a side: the module is not env-gated and runs by default (3 tests pass), while the single catalog-drift assertion inside it is suspended by the provable tear (1 skips). Nothing else in the five reports contradicted anything else; the remaining differences were all corrections to the earlier 2026-08-08 traces rather than disputes between tracers.
