## Anomalies

1. **The Atlas 3.0 builder itself is unwired.** `tools/generate_atlas_v3_full.py` — 10,294 lines, by far the largest script in the repo, and the file the prior doc calls "Atlas 3.0 builder + explorer," the component nearest the product thesis — does not appear in the Makefile at all (`grep generate_atlas_v3_full Makefile` → no match). It's only reachable via a direct import from `build_atlas_native_relation_testsets.py` and one test. The Makefile's `audit-atlas-v3-source-fidelity` target *consumes* a pre-built distribution directory but never invokes the builder that produces it. This is the most consequential instance of "unwired," and it's absent from the prior investigation's framing, which reads as if the unwired set were mostly disposable experiment scripts.
2. **A generate/verify pair is split across the wiring boundary.** `tools/build_registry_source_manifest.py` produces `research/evidence/registry-real-data-audit-2026-08-03/sources.json`, which the Makefile-wired `tools/verify_registry_audit.py` requires as input (confirmed by reading `verify_registry_audit.py` line 25). The generator is TEST-SUPPORT only — nothing but a test calls it — so the checked-in manifest can silently drift from the registry code with no `make` target catching it.
3. **`tools/build_atlas_parquet_view.py` is a dead wrapper**, not an experiment. It has zero references anywhere in the repo and is fully superseded by the `pyproject.toml` console-script entry `refspec-build-atlas-parquet-view = "refspec.atlas.parquet_view_cli:main"`. The earlier apparent "importer" hits for this filename were a false positive — an unrelated same-named Python *function* in `src/refspec/atlas/parquet_view.py`.
4. **Two apparent cross-tool import edges were docstring prose, not code.** `verify_atlas_crosswalk_benchmarks.py` mentions `build_atlas_crosswalk_benchmarks.py` only in a comment; `benchmark_atlas_dense_relation_recovery.py`/`optimize_atlas_native_relation_frontier.py` mention `benchmark_atlas_native_relation_recovery.py` only in prose. A naive substring grep (which I ran first, then verified line-by-line) would have overcounted the IMPORTED class by 2. Worth flagging since this repo's benchmark scripts frequently cross-reference each other in docstrings for provenance, which is easy to mistake for wiring.
5. **`run_atlas_qualification.py` is invoked from production-adjacent code via subprocess, not import** — `src/refspec/atlas/qualification_jobs.py` shells out to it by relative path string. This is a real coupling the "imported by src/refspec code" definition doesn't cleanly capture (it's not a Python `import`), but it means this tool is far from a pure standalone script, and the coupling is still entirely within the research-only qualification cluster — it never reconnects to `generate_atlas_v3_full.py` or a console-script entry point.
6. **The `build_*_blind_review.py` / `compare_*_blind_review.py` pattern is inconsistent.** For `relatedmatch` and `variant_classifier`, both build/compare halves have test coverage. For `crosswalk`, neither `build_atlas_crosswalk_blind_review.py` nor `compare_atlas_crosswalk_blind_review.py` has any test or importer — the identical-shaped sibling pipeline has zero verification.
