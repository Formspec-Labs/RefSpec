Workspace map — five repos, one ownership boundary

What each repository is, what it owns, what it consumes, and what will bite you. Four repos are yours. One is not, and that single fact explains most of the architecture. Written to be consulted, not read through.

Code is authoritative. This is a map. The investigation behind this page ran under one rule — ignore every .md file, trace code instead — because prose in this workspace consistently overstated what was blocked and understated what was built. A prose source of truth inherits exactly that risk. Re-derive before you rely on anything here. Every figure below carries the evidence that produced it, and where a number is recomputable, the command that recomputes it and the date it was last taken.

Reading conventions. file:line is a citation into a checkout. command is a re-derivation you can run. A ASSERTED pill means the claim rests on prose rather than on disk, and the file is named. Commands assume WS=~/Work, holding spicy-regs/ (with RefSpec/ nested inside it), rulespec/, DocSpec/ and spicysearch/.

Standing limits on everything below. Reachability is import-graph tracing, not runtime coverage — a rare dynamic-dispatch pattern could invalidate an individual “unreached” verdict. Every production row count in this workspace is asserted, not measured: the canonical tables live in a Cloudflare R2 Iceberg catalog whose credentials are absent from .env, and no trace made a network call. The rule that falls out is symmetric and short: nothing you own may import what you don't, and nothing you don't own may import you. It is violated in both directions today. Each violation is load-bearing on something different, which is why none is a one-line fix.

One edge already has the shape the rule asks for. Every SpicySearch → SpicyRegs edge is an owned repo consuming a not-owned repo's published artifacts — vendored, digest-pinned, never imported. Copy that pattern rather than inventing a new one.

Why this is not an emergency, and exactly when it becomes one. No code anywhere branches on the coordinate-system string to choose byte-versus-codepoint arithmetic. Every numeric consumer hard-codes its own producer's assumption unconditionally — DocSpec always byte-slices, SpicyRegs always codepoint-slices, RuleSpec's validator only checks start > end ordering and never reads the unit, and SpicySearch validates membership in its own two local spellings rather than converting. Conversion stays feasible only while the inputs survive. SpicyRegs stores the literal text slice inline, so its records convert with no lookup. RuleSpec's digest fields are optional, so records omitting them are unconvertible.

Respelling is cheap in logic and not free in provenance. unicode-codepoints-half-open, rkaf:unicode-codepoint and unicode-code-points all describe the same arithmetic; respelling changes no offset. But the string sits inside the canonicalised payload, so respelling changes artifact IDs and invalidates every receipt taken over the old form. Do it once, deliberately, not incrementally. The work in order: (a) settle byte-vs-codepoint with DocSpec — a design negotiation and the only expensive item; (b) decide once whether to respell the codepoint family, accepting that artifact IDs move; (c) make the conforming producer actually produce, since today it has six records to its name.

This page replaced one that had taken six amendment passes over three days, each appending rather than integrating, until most findings appeared two or three times in different states and no reader could tell which version was current.
